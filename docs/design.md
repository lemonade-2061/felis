# felis設計(メモ)

## 概要

レイアウトが値なのでundo/保存/復元ができるWM

## 設計

### Bindingのマッチ規則

- titleは動的に変わるので完全一致のキーにすると壊れやすい
- app_idだけでマッチし、同じapp_idが複数あるときは木の深さ優先順に詰める

### 余り処理のポリシー

- 葉が余ったとき: 潰す(`remove` の縮約処理を再利用)
  - 空枠として残すと、実行時の木に中身のない葉が入り不変条件が崩れる。描画・focus・待ち時間など決めることも増える
  - 「後から起動したら埋める」が欲しくなるのは機能B(app_id でのセッション復元)。その時は木の外に待ち受けリストとして持つ
- ウィンドウが余ったとき: 最後の葉に add(新規ウィンドウと同じ挙動、既存処理を再利用)
  - floating に出すのはタイル優先の WM では驚きの方が大きい

### coalescingの閾値と何を1ステップとみなすか

- focus の移動は積まない。代わりに `WorkspaceSnapshot` に focus 中のウィンドウを含める
  - undo すると focus が操作した場所に戻る(エディタの Ctrl+Z でカーソルが編集箇所に戻るのと同じ)
- ドラッグは押してから離すまでで1ステップ。押した時点のスナップショットを離した時に積む
- before == after なら積まない(`WorkspaceSnapshot` に `PartialEq`)
  - 端で失敗した移動/resize や、何も変えなかったドラッグで Ctrl+Z が空振りしない
- 時間の閾値がいるのはキーリピートで連続した resize だけ
  - 同種・同ワークスペース・500ms 以内ならまとめる(新しく積まない)。値は触って調整

### undoの範囲

- 最初は per-workspace のみ。undo-global は後回し
- floating を undo に含める
